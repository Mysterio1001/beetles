# Beetles Vue 3 全站重建 Specification

## Problem

舊版網站具有完整品牌內容與 11 頁靜態導覽，但結構重複、桌面與手機內容重複維護，會員與交易流程只有固定畫面。現有 Vue 3 專案已具備部分基礎，仍缺少多數頁面、跨頁狀態、正式資料邊界、完整雙語、靜態部署路由及一致的品質驗證。

## Goals

- 交付一個可完整瀏覽及操作的 Vue 3 甲蟲品牌網站。
- 重建舊版內容與核心流程，同時改用現代綠色液態玻璃視覺。
- 讓消息、文章、商品、會員、購物車與結帳資料可集中維護及替換。
- 提供一致的繁體中文與英文體驗。
- 讓訪客或 Mock 會員都能完成商品到訂單完成的前端流程。
- 在 GitHub Pages 類靜態主機上可靠運作。

## Non-goals

- 不建立真實會員、授權、付款、物流、庫存或訂單服務。
- 不保存或傳送真實信用卡資料。
- 不提供跨瀏覽器、跨裝置的資料同步。
- 不逐像素複製舊版 CSS。
- 不支援 Internet Explorer。
- 本階段不建立 Vitest、Vue Test Utils、Playwright 或 CI 測試流程。

## Users and scenarios

### 訪客

- 瀏覽首頁、消息、研究文章、商品與品牌資訊。
- 搜尋、篩選及排序內容。
- 將商品加入購物車並以訪客身分結帳。
- 註冊或使用預設測試帳號登入。

### Mock 會員

- 使用帳號或電子郵件登入。
- 登出並回到訪客狀態。
- 在結帳時帶入本機會員資料。

### 維護者

- 在集中資料來源更新雙語消息、文章、商品與選項。
- 替換 Mock data import 邊界，而不更改頁面呈現與互動契約。
- 在頁面樣式與元件樣式的既定邊界內維護視覺。

## Required behavior

### 1. 全站 Shell 與路由

- 使用者可透過 Header 前往首頁、最新消息、甲蟲研究所、翅鞘商店及羽錄情報。
- Header 必須提供首頁 Logo、語言切換、會員入口／狀態及購物車入口與數量。
- 登入後會員入口顯示可識別的會員狀態與登出操作；登出後立即恢復訪客狀態。
- Footer 顯示品牌、版權與可用的社群外部連結。
- 非首頁頁面顯示與目前路由階層相符的麵包屑。
- 網站以 hash URL 導覽；使用者直接開啟或重新整理任一有效 hash 頁面都能載入正確內容。
- 未匹配路由顯示雙語 Not Found 畫面，並提供返回首頁的操作。
- 每次頁面導覽後更新文件標題並將主要內容捲動至頂端。

### 2. 視覺、互動與動態效果

- 全站以深淺綠色、半透明層、背景模糊、柔和邊框及高光建立一致的液態玻璃視覺。
- 文字與互動控制項必須在玻璃背景上維持清楚對比。
- 可點擊的按鈕、連結、卡片、標籤、選單及社群入口提供一致的 hover、active 與 focus-visible 回饋。
- 不具操作能力的裝飾元素不得呈現成可點擊樣式。
- 使用者偏好 reduced motion 時，非必要位移、縮放、循環與自動動畫必須停用或縮短；內容不可因此無法存取。
- 鍵盤使用者可以操作導覽、選單、對話框、表單、商品與結帳流程。

### 3. 響應式行為

- 同一份內容結構自動適應手機、平板與桌面，不建立兩套重複的業務資料或互動狀態。
- Header 在窄螢幕切換為行動選單；開啟時可關閉、可阻止背景誤操作，導覽完成後自動收合。
- 卡片、商品格線、表單、購物車摘要與結帳區塊在 375px 不產生非預期水平捲動。
- 在 768px、1024px 與 1440px 下，內容密度、欄數與留白隨可用空間調整。

### 4. 語言

- 網站正式支援繁體中文與英文。
- 若尚未保存使用者選擇，中文瀏覽器語言顯示繁體中文；英文瀏覽器語言顯示英文；其他語言顯示英文。
- 使用者在 Header 切換語言後，全站導覽、頁面文字、表單、訊息、商品、消息與文章在不重新載入頁面的情況下同步切換。
- 手動選擇跨重新整理與後續造訪保留，並優先於瀏覽器語言。
- 文件標題、麵包屑、空狀態、錯誤與通知必須跟隨目前語言。
- 缺少翻譯時使用英文回退內容，不顯示翻譯 key。

### 5. 資料來源

- 消息與文章以現有 Vue 測試資料為內容基準；舊版內容只補足未涵蓋的領域。
- 首頁內容、商品、商品分類、配送、Mock 門市及預設會員等資料必須集中管理。
- 頁面不得直接宣告消息、文章、商品、分類、配送、門市或會員資料集合。
- 每筆可導覽資料具有穩定識別值；標題或翻譯變更不應破壞既有詳情連結。
- 圖片載入失敗時保留版面並顯示可理解的替代文字或 fallback。

### 6. 首頁

- 首頁顯示品牌 Hero、品牌介紹、近期到貨商品及最新飼育紀錄。
- 近期到貨項目可前往對應商品詳情。
- 飼育紀錄項目可前往對應文章詳情。
- 首頁主要內容在所有驗收尺寸均可閱讀，視覺動效不得阻止使用者操作。

### 7. 最新消息

- 頁面顯示消息輪播、分類標籤及消息卡片。
- 分類至少包含全部、公告、活動及飼育情報。
- 選擇分類後只顯示符合的消息；再次選擇全部恢復完整列表。
- 點擊消息卡片顯示完整雙語標題、圖片與內容。
- 對話框可由關閉控制、Escape 鍵及合理的背景操作關閉，開啟時焦點維持在對話框範圍。
- 輪播可手動切換；自動播放在使用者互動後不造成突兀跳動，且遵守 reduced-motion。
- 沒有符合內容時顯示目前語言的空狀態。

### 8. 甲蟲研究所與文章詳情

- 研究所顯示文章列表、最新文章入口、關鍵字搜尋及分頁控制。
- 搜尋以目前語言的文章標題及摘要進行不區分大小寫的部分比對。
- 搜尋字串清空後恢復完整列表並回到有效頁碼。
- 最新文章入口與文章卡片都能前往穩定的文章詳情 URL。
- 文章詳情顯示標題、日期、主圖及完整內容，並可返回文章列表。
- 找不到文章識別值時顯示文章不存在狀態及返回列表操作，不造成應用錯誤。

### 9. 翅鞘商店

- 商店顯示商品搜尋、分類、排序、結果數、商品格線及分頁。
- 搜尋比對目前語言的商品名稱、學名及關鍵字。
- 商品分類至少涵蓋新品、成蟲、幼蟲、耗材、標本、飼育用品及教學課程；資料為空的分類仍顯示明確空狀態。
- 排序支援價格高到低、價格低到高、日期新到舊、日期舊到新及預設順序。
- 搜尋、分類與排序可以共同作用；結果變更後頁碼回到有效範圍。
- 商品卡顯示圖片、雙語名稱／學名、價格與可用狀態，並前往商品詳情。

### 10. 商品詳情

- 商品詳情顯示主圖、名稱、學名、價格、產地、親代、類別、累代、尺寸、狀況及說明；不存在的欄位不顯示空標籤。
- 使用者可選擇可用規格及正整數數量；數量不得低於 1。
- 加入購物車後顯示成功回饋並更新 Header 購物車數量。
- 相同商品與相同規格再次加入時合併數量，不建立重複列。
- 「立即購買」加入選定項目後前往購物車。
- 頁面顯示相關商品及相關文章；可用項目導向對應詳情。
- 找不到商品識別值時顯示商品不存在狀態及返回商店操作。

### 11. Mock 會員登入

- 登入表單接受帳號或電子郵件與密碼。
- 正確的預設帳號或本機已註冊帳號可登入；成功後建立持久化登入狀態並導向合理的上一頁或首頁。
- 錯誤憑證顯示表單錯誤，不得建立或保留錯誤登入狀態。
- 已登入使用者進入登入頁時導向首頁。
- 忘記密碼顯示明確的 Mock 提示，說明不會寄送真實郵件。

### 12. Mock 會員註冊

- 註冊欄位包含帳號、電子郵件、密碼、確認密碼、姓名、電話、生日與地址資料。
- 帳號、電子郵件、密碼、確認密碼、姓名及電話為必填；生日與地址可由使用者填寫並保存於本機會員資料。
- 帳號與電子郵件不得和預設或本機會員重複。
- 電子郵件必須符合一般電子郵件格式；電話必須是 10 位數字。
- 密碼長度為 6 至 12 字元，且至少包含大寫英文、小寫英文與數字；確認密碼必須一致。
- 生日選項必須符合實際月份天數與閏年規則。
- 驗證失敗時顯示各欄錯誤且不建立會員；成功時保存會員並引導登入。

### 13. 購物車

- 購物車顯示每個商品／規格、單價、數量、小計及移除操作。
- 使用者可修改為正整數數量；數量及小計立即更新並持久化。
- 移除最後一項後顯示空購物車狀態與返回商店操作。
- 配送方式包含 7-ELEVEN 70 元、全家 70 元、黑貓宅急便 150 元、自行取貨 0 元。
- 配送方式變更後運費及總額立即更新。
- 空購物車不能進入結帳；嘗試進入時停留或返回購物車並顯示提示。

### 14. 結帳

- 訪客與登入會員都可進入非空購物車的結帳頁。
- 登入會員可選擇帶入本機會員姓名、電話及地址；使用者仍可修改帶入內容。
- 收件人姓名與 10 位數電話為必填。
- 黑貓宅配要求完整地址；7-ELEVEN 或全家要求選擇對應的 Mock 門市；自行取貨不要求地址或門市。
- 支援銀行轉帳與信用卡付款方式。
- 選擇銀行轉帳時不要求信用卡欄位。
- 選擇信用卡時要求持卡人、16 位卡號、未過期的有效期限及 3 位安全碼。
- 訂單摘要顯示商品、數量、小計、配送、運費及總額，並和購物車狀態一致。
- 驗證失敗時停留在結帳頁、顯示欄位錯誤並保留非敏感內容。
- 送出成功後產生唯一可識別的 Mock 訂單編號、建立當次完成狀態並清空購物車。
- 任何卡號、安全碼及信用卡有效期限不得寫入持久化儲存。

### 15. 訂單完成

- 有效訂單完成狀態顯示成功訊息、Mock 訂單編號、訂單總額、社群入口及五秒倒數。
- 倒數結束後返回首頁；使用者可在倒數前手動返回首頁。
- 完成頁重新整理或在沒有有效新訂單狀態時直接開啟，必須返回首頁。
- 頁面離開後停止倒數計時，不得在背景重複導覽。

### 16. 羽錄情報

- 顯示品牌介紹、服務範圍、主要視覺、聯絡電話與社群連結。
- 電話入口使用可撥號連結；社群連結在新頁面安全開啟。
- 桌面動畫與手機主圖都不得遮擋主要文案或操作。

### 17. 分頁、空狀態與通知

- 分頁只在結果超過單頁容量時出現，顯示目前頁、總頁數及可用的上一頁／下一頁操作。
- 篩選或搜尋造成目前頁不存在時，自動移至第一個有效頁面。
- 空狀態提供原因及最相關的下一步操作。
- 成功、警告及錯誤通知在目前語言顯示，不應只依靠顏色傳達狀態。

## Edge cases and failure behavior

- 儲存的語言值無效時移除無效值並依瀏覽器語言重新選擇。
- 儲存的購物車、會員或登入資料無法解析、schema 不符或引用不存在項目時，丟棄無效部分並維持網站可用。
- 購物車中的商品後續不存在時不計入總額，並提示使用者移除或自動清理。
- 商品價格、數量與運費計算使用整數新台幣，不顯示浮點誤差。
- 快速重複送出登入、註冊或結帳不得建立重複會員、重複訂單或重複導覽。
- 外部連結必須避免讓新頁面控制原頁面。
- 所有圖片具備符合內容的替代文字；純裝飾圖片不重複朗讀無意義資訊。

## Data, permissions, and external contracts

- Mock data、翻譯、頁面、跨頁狀態及儲存存取是不同責任邊界。
- 只有語言選擇、Mock 註冊會員、目前登入狀態與購物車允許持久化。
- 收件表單、付款欄位與有效完成訂單狀態僅存在當次操作期間。
- 本網站不要求裝置權限、不呼叫真實會員或交易服務。
- 共用元件樣式位於元件自身；頁面樣式位於 `src/style/page/` 並由 `src/style/main.scss` 匯出。
- 靜態圖片必須使用部署後可解析的 URL，不依賴開發伺服器對錯誤 public 路徑的兼容。

## Compatibility, rollout, and recovery

- 支援最新版 Chrome、Safari、Firefox 與 Edge。
- 正式產物可直接部署到 GitHub Pages 類無 rewrite 靜態主機。
- 新版以 `codex_dev` 分支開發，不覆寫使用者未追蹤檔案。
- 發布前逐頁驗證 375px、768px、1024px、1440px，並執行 ESLint、Prettier 檢查與 production build。
- 新版若遇到無法復原的本機 Mock 狀態，清除對應狀態後仍可使用集中預設資料啟動。

## Constraints and assumptions

- UI 與資料內容都必須完整雙語。
- 元件不得將業務 Mock 資料寫死於 template 或 script。
- 頁面可保留舊版品牌意象，但版面與互動以新版規格為準。
- 本機 Mock 憑證、會員與訂單不代表正式安全機制，使用者不應輸入真實敏感資料。
- 自動化測試延後不降低本次 lint、build、功能與視覺驗證要求。

## Acceptance criteria

1. 所有指定頁面與詳情狀態可由全站導覽或流程到達；hash 子頁重新整理可正常載入，未知路由顯示 Not Found。
2. Header、Footer、麵包屑、語言、會員狀態與購物車數量在各頁行為一致。
3. 繁中與英文可即時切換；未知瀏覽器語言使用英文；手動選擇可跨工作階段保存。
4. 所有使用者可見資料皆有雙語內容，缺少翻譯時不顯示 key。
5. 頁面不直接宣告業務 Mock 資料集合，且資料來源存在明確可替換邊界。
6. 首頁商品與文章入口、消息分類與對話框、文章搜尋與詳情均可完成。
7. 商店搜尋、分類、排序、分頁與商品詳情共同運作，無結果時顯示正確空狀態。
8. 商品規格與數量可加入購物車；相同項目合併，Header 數量、列小計、商品小計、運費及總額一致。
9. 預設會員及本機註冊會員可登入／登出；註冊與登入錯誤不建立錯誤狀態。
10. 訪客及會員均可依四種配送方式完成條件式收件與付款驗證。
11. 成功結帳只產生一筆 Mock 訂單、清空購物車，並在完成頁顯示訂單編號及五秒倒數。
12. 信用卡欄位、收件表單與完成狀態未寫入持久化儲存。
13. 空購物車、無有效訂單、未知商品、未知文章與損壞儲存資料均依規格安全復原。
14. 液態玻璃綠色主題、hover、active、focus-visible 與 reduced-motion 在四種驗收寬度可正常使用。
15. 最新版 Chrome、Safari、Firefox、Edge 沒有阻擋核心流程的錯誤。
16. ESLint、Prettier 檢查及 production build 全部通過，正式產物沒有錯誤 public 資產路徑。

## Deferred decisions
